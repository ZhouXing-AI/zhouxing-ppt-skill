# 十二套主题的30页能力样稿

每套中英文各30页，共24份演示、720页（每种语言360页）。首次公开版本仍为1.0.0。30是样稿能力清单，不是用户生成演示的固定长度；中英翻译、改数据和换配图不单独计为新版式。原有前9页保留，原收尾移动到30页。

## 公共能力与页码

| 页 | 能力 | 使用条件 |
|---|---|---|
| 1–9 | 各主题的封面、观点、图文、关系及叙事布局 | 沿用主题自己的构图；按用户内容选择，不必全用 |
| 10 | 四列内容卡片 | 四个并列对象；数量改变需重新检查列宽与文字 |
| 11–14 | 垂直柱、水平柱、象形柱、分组柱 | 比较同口径数量；共用零基线与尺度；象形须标明一枚的单位 |
| 15 | 百分比堆叠 | 比较组成，各组明确分母并合计100% |
| 16 | 瀑布 | 初始量、增减量、最终量闭合，负值不能按绝对值画 |
| 17–18 | 折线、面积 | 明确时间间隔；面积有零基线，不擅自平滑产生新峰谷 |
| 19 | 雷达及数值对照 | 维度和量表一致；保留数值，不能用面积宣称综合质量 |
| 20 | 桑基 | 流量守恒，各层、各节点及流带厚度由同一组数据计算 |
| 21–22 | 散点、热力 | 坐标、色阶及单位明确；不以相关性宣称因果 |
| 23 | 目标进度 | 实际值、目标线和差值分别显示，保留超过目标的部分 |
| 24 | 独立数据表 | 多列真实信息；单位、口径与总计明确，异质单位不得合计 |
| 25 | 方案对比矩阵 | 维度为行、方案为列，逐项可横向比较；不是重复卡片页 |
| 26 | 阶段时间轴／甘特安排 | 阶段顺序、开始和持续时间清楚，不任意改变时间比例 |
| 27 | 分支决策流程 | 判断节点、条件、处理路径和修改出口明确；不同于数量流向图 |
| 28 | 环形占比 | 单一总体下的互斥类别合计100%，同图显示比例与必要数值 |
| 29 | 漏斗 | 同一批对象逐阶段保留，明确转化率分母；等高条宽表示数量 |
| 30 | 各主题原有收尾 | 沿用原收尾视觉和素材，页码由播放器自动计算 |

以上覆盖常用表达，不代表所有行业分析模型、复杂泳道、树图或任意大数据表均有固定模板。特殊场景应按主题规则重新编排，并验证内容和读数。

## 复用方式

十二套工作副本均含 `source/expansion30.py`。它提供 `get_slides(lang)` 和 `validate_data()`：前三套返回新增第24–29页六个片段，后九套返回第10–29页二十个片段。先在工作副本修改数据和文案，运行校验，再生成所需片段：

```sh
python3 scripts/render_layout_extensions.py --project /absolute/path/to/deck --lang zh-CN --output /absolute/path/to/new-sections.html
```

输出是依赖工作副本CSS与播放器的section片段，不是完整HTML。选择合适片段放入 `source/slides.html` 后再用 `build_deck.py` 编译。前三套第10–23页仍使用原有 `source/chart-recipes/` 与对应 `render_*_data_slides.py`。新增CSS与原主题样式合并，修改时同步相应源文件。

示例数据和业务场景为原创虚构，记录在配方、参考资料和deck.json元数据；不在画面加「示例数据」、图表类型或制作标签。生成真实演示时使用用户资料或已核实信息。改变数值必须同步更新几何、标签、单位和结论；浏览器的文字编辑不会自动重算图表。

## 审美与验证

新增版式继续使用每套已确认的完整许可字库、配色、线条与造型。图表准确度优先于材质表现，不强制3D。题头上移并与图表拉开至少60px（1920×1080画布），正文不侵占底部导航。不同页面交替使用全宽、分栏、并列比较和数值引导等构图；不把全部图表放入同一种卡片模板。

中英文应分别检查长标题、标签、单位、表格行列与字体覆盖。用户内容增加时按内容重排；不可通过缩小所有文字或删掉必要条件来勉强塞进样稿。

所有信息图采用有限入场动画，统一纳入播放器的结束与取消流程。减少动态、编辑、保存、导出时保留完整静态图形。新增页面不进入装饰素材替换库，十二套各24张SVG保持不变。预览、实际生成和下载使用同一份成品HTML。

用户选风格与内部版式库分开：快速选择只需展示少量风格预览；完整30页样稿供深入浏览，不要求用户逐页挑选。

环形占比优先用按真实数值计算的封闭扇区路径，不用虚线圆圈叠出分段，避免HTML转图像时在首尾交接处产生错位。各扇区的角度和图例必须来自同一份数据。
